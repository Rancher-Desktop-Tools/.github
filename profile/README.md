## What Rancher Desktop Brings to Container Workflows

Rancher Desktop provides a desktop environment for working with containers and Kubernetes on a local development machine. It brings container runtime controls, Kubernetes configuration, and related command-line tooling into one workspace.

Container workflows can be managed through supported runtime options and familiar container commands. This makes the application useful for developers who need a local environment for building, testing, and inspecting containerized applications.

Kubernetes integration provides a local cluster environment for development and testing. Users can configure Kubernetes settings and work with cluster resources through tools such as kubectl.

K3s can provide the lightweight Kubernetes foundation used by Rancher Desktop. This makes the environment practical for local development scenarios where a compact cluster is useful for testing applications and Kubernetes configurations.

Docker-compatible workflows are another important part of the environment. Developers can use familiar container commands and workflows while working with projects that rely on container images and services.

The application also supports configuration of the container runtime. Depending on the selected setup, developers can adjust the environment according to the requirements of their projects and preferred development workflow.

WSL integration can connect Rancher Desktop with Windows development environments that use the Windows Subsystem for Linux. This can be useful when development tools, command-line workflows, and container projects are distributed across the Windows and WSL environments.

Container management tasks can include starting, stopping, inspecting, and working with locally available containers. These operations provide a practical foundation for everyday development and testing.

Kubernetes configuration can also be adjusted when a project requires different cluster behavior. Developers can enable or disable Kubernetes according to whether the current workflow requires a local cluster.

Rancher Desktop can work alongside development environments such as Visual Studio Code. This allows containerized projects to be edited and tested from a familiar development workspace while Rancher Desktop handles the underlying local infrastructure.

The desktop interface provides visibility into important environment settings without requiring every configuration task to be performed exclusively from a terminal. This can make local container development easier to manage.

For projects involving multiple services, a local container environment can simplify testing before deployment to a larger infrastructure environment. Developers can reproduce application dependencies and service interactions on their own machines.

Overall, Rancher Desktop combines container management, Kubernetes development, runtime configuration, and Windows-oriented tooling into a practical local development workspace.

## Starting a Rancher Desktop Workspace

**Prerequisites:** A Windows computer with hardware virtualization enabled, supported WSL capabilities, and sufficient storage for container and Kubernetes resources.

1. Install Rancher Desktop on the Windows computer and complete the initial setup.
2. Launch Rancher Desktop and review the available container runtime and Kubernetes settings.
3. Configure the preferred runtime and enable Kubernetes when the project requires a local cluster.
4. Verify WSL integration and confirm that the required command-line tools are available.
5. Start a test container or inspect the local Kubernetes environment to verify the configuration.
6. Open the development project and begin working with the configured container or Kubernetes workflow.
